قدم ۱ README و هدف پروژه

فایل: README.md

پروژه سه قابلیت دارد:

  • RAG — پاسخ از روی PDFها (سیاست بازگشت، handbook، کاتالوگ)
  • NL2SQL — سوال فارسی/انگلیسی → SQL خواندنی روی SQLite
  • Agentic flow — LangGraph مسیر rag / sql / hybrid را انتخاب می‌کند

قدم ۲ تنظیمات و قرارداد API

۲‑۱ — app/config.py

کلاس Settings (با pydantic-settings) همهٔ تنظیمات را از محیط/.env می‌خواند: کلید OpenAI، مدل LLM، مدل Embedding محلی، مسیر پوشهٔ اسناد، مسیر FAISS، مسیر دیتابیس، و پارامترهای RAG مثل rag_top_k و rag_min_score.

تابع get_settings() با کش (lru_cache) یک بار تنظیمات را می‌سازد تا در همهٔ ماژول‌ها یکسان باشد.

۲‑۲ — .env.example

الگوی متغیرها: OPENAI_API_KEY برای Router و تولید پاسخ لازم است؛ Embedding محلی است و به کلید نیاز ندارد.

۲‑۳ — app/models/schemas.py

قرارداد ورودی/خروجی با Pydantic:

مدلنقش
AskRequest question + اختیاری force_route (auto / rag / sql / hybrid)
AskResponse پاسخ نهایی: answer، route، sources، sql، calculator، trace، …
SourceCitation استناد به تکهٔ سند در مسیر RAG
TraceStep یک گام از ردپا برای دیباگ (کدام agent چه کرد)
HealthResponse وضعیت سلامت API، DB و ایندکس

قدم ۳ دروازهٔ FastAPI — app/main.py

نقطهٔ ورود برنامه. وقتی سرور بالا می‌آید:

  1. lifespan اجرا می‌شود: اول ensure_database() دیتابیس را آماده می‌کند، بعد ensure_rag_ready() ایندکس FAISS را لود یا می‌سازد.
  2. GET /health — وضعیت DB، RAG و کلید LLM را گزارش می‌دهد.
  3. POST /ask — سوال را می‌گیرد و run_assistant(...) را صدا می‌زند. این مهم‌ترین endpoint است.
  4. endpoint کمکی: POST /sql/validate — نشان می‌دهد SQL خطرناک (مثل DROP) بدون دخالت LLM رد می‌شود.

قدم ۵ مسیر RAG — از PDF تا پاسخ

  1. app/rag/preprocess.py — متن PDF را تمیز می‌کند: حذف هدر/فوتر، اصلاح خط‌تیره‌ها، نرمال‌سازی یونیکد، و chunk_text برای تکه‌تکه کردن سند.
  2. app/rag/ingest.py — Embedding محلی (MiniLM)، ساخت یا لود FAISS در data/faiss_index، و ensure_rag_ready که در استارتاپ صدا زده می‌شود.
  3. app/rag/retriever.py — retrieve نزدیک‌ترین chunkها را می‌آورد؛ اگر امتیاز پایین باشد insufficient_context=True و جواب ساختگی نمی‌دهد. وگرنه LLM فقط از همان context با citation پاسخ می‌دهد (answer_from_documents).
  4. app/agents/rag_agent.py — لایهٔ نازک: فقط answer_from_documents را صدا می‌زند تا coordinator تمیز بماند.

قدم ۶ مسیر SQL — از سوال تا کوئری امن

  1. app/sql/db.py — اسکیما (products، sales)، دادهٔ نمونه، ensure_database، توضیح اسکیما برای LLM، و get_readonly_connection (اتصال فقط‌خواندنی با authorizer).
  2. app/tools/database.py — ابزار query_database(sql) که LLM با tool calling صدا می‌زند. خطا را به‌جای استثنا به‌صورت JSON برمی‌گرداند تا LLM کوئری را اصلاح کند.
  3. app/sql/nl2sql.py — اعتبارسنجی و اجرا:
    • validate_readonly_sql — فقط یک SELECT/WITH؛ DROP/INSERT و … ممنوع (داخل رشته‌ها و کامنت‌ها نادیده گرفته می‌شود)
    • run_query — اجرا با سقف تعداد ردیف و timeout؛ هیچ‌وقت استثنا پرتاب نمی‌کند
  4. app/agents/sql_agent.py + tool_agent.py — حلقهٔ tool calling: LLM کوئری می‌نویسد، نتیجه (یا خطا) را می‌بیند، در صورت نیاز اصلاح می‌کند و در پایان پاسخ را می‌سازد (سقف تعداد مرحله).

قدم ۷ ماشین‌حساب و مسیر Hybrid (Tool Calling)

فایل‌ها: app/tools/calculator.py و app/agents/hybrid_agent.py

  • safe_calculate — عبارت ریاضی را با AST امن ارزیابی می‌کند (بدون eval)
  • calculator_tool — همان تابع به‌شکل ابزار LangChain؛ خطاها به‌صورت JSON به LLM برمی‌گردند
  • توابع کمکی: pct، pct_change، avg، round، min، max، sqrt

hybrid_agent هر دو ابزار query_database و calculator را به LLM می‌دهد (bind_tools). خود LLM تصمیم می‌گیرد چند بار SQL بزند و چه چیزی را حساب کند؛ دیگر هیچ regex یا ساخت دستی عبارتی در کار نیست.

جریان اجرا در زمان واقعی

وقتی کاربر می‌پرسد «مشتری چند روز برای بازگشت کالا فرصت دارد؟»:

  1. درخواست به POST /ask می‌رسد (main.py).
  2. run_assistant گراف را با سوال اجرا می‌کند.
  3. Router تشخیص می‌دهد موضوع سند است → مسیر rag.
  4. rag_node → retrieve از FAISS → LLM پاسخ grounded می‌دهد.
  5. AskResponse با answer، sources و trace برمی‌گردد.

اگر بپرسد «مجموع درآمد فروش چقدر است و ۱۵ درصدش چند می‌شود؟»:

  1. Router مسیر hybrid را انتخاب می‌کند.
  2. Hybrid Agent با tool calling query_database را صدا می‌زند (در صورت خطا کوئری را اصلاح می‌کند).
  3. LLM همان عدد را به calculator می‌دهد و ۱۵٪ را حساب می‌کند.
  4. پاسخ شامل sql، sql_result، calculator، tool_calls و trace است.
